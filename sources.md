- Официальный Python SDK MCP, версия v1.26.0:
  https://github.com/modelcontextprotocol/python-sdk/tree/v1.26.0
  README: Low-Level Server / Structured Output Support / Writing MCP Clients.
  Используются стандартный stdio-транспорт, ClientSession и явные схемы low-level сервера.

Решение: композиция сервиса расписания и MCP-адаптера; сервис не зависит от Telegram
или протокола. Часы передаются параметром для воспроизводимых проверок границ недели.
Low-level API выбран для точных схем с запретом лишних аргументов; FastMCP уменьшил бы
объём кода, но потребовал бы отдельно контролировать генерируемые схемы аргументов.

- OpenRouter, Client Tools / Chat Completions API:
  https://openrouter.ai/docs/guides/features/tool-calling
  Прочитан 15.11.2026. Модель возвращает assistant.tool_calls; приложение выполняет
  инструмент и возвращает role=tool с tool_call_id. Схемы tools передаются на каждом
  запросе, ответ инструмента является данными, не системной инструкцией.

Проверка отказа MCP: текущий клиент в WSL с прежним лимитом не подключился за
12,39 секунды (с учётом закрытия процесса). После увеличения стартового лимита
до 60 секунд подключение успешно за 10,98 секунды. Обычные запросы сохраняют
отдельный предел 10 секунд. Исходное ExceptionGroup не сохраняло вложенную причину;
новая диагностика пишет этап, типы вложенных исключений и числовой MCP-код.

Совместимость tool calling, проверка 15.11.2026:
https://openrouter.ai/docs/api_reference/overview, раздел CompletionsResponse format.
Официальная схема перечисляет id/type/function. В реальном ответе настроенного
провайдера дополнительно наблюдался index: finish_reason=tool_calls, один вызов,
arguments имеет тип str; прежний валидатор выдавал extra_forbidden по полю index.
Проверка отправляла только вымышленный вопрос, без пользовательской истории.
Адаптер принимает известное индексное поле как метаданные и удаляет его при
нормализации; контракты аргументов MCP и запрет неизвестных полей не ослаблены.

Погода (16.11.2026): https://open-meteo.com/en/docs и
https://open-meteo.com/en/docs/geocoding-api — прочитаны; текущие поля погоды,

Личные расписания и MCP-контекст: официальный SDK v1.26.0, client/session.py
ClientSession.call_tool(meta=...), server.request_context.meta — проверены по
установленным исходникам SDK. Контекст владельца передаётся отдельно от аргументов
модели, подписывается HMAC-ключом, генерируемым приложением на время соединения.
PostgreSQL владеет состояниями подтверждения и уникальностью действия; сообщение
пользователя не считается согласием на ещё не показанные нормализованные параметры.

Геокодирование Санкт-Петербурга: 16.11.2026 воспроизведён реальный ответ API с
двумя местами, где у второго отсутствует country, но есть country_code=MS и
admin1=Parish of Saint Peter. Согласно ранее прочитанной документации геокодинга
пустые поля могут отсутствовать; ISO country_code является отдельным полем.
Теперь сохраняется неоднозначность обоих результатов с достоверным кодом страны,
а не выбирается первый город и не отвергается весь ответ из-за отсутствия перевода.

Поиск Еревана (16.11.2026): реальный геокодинг вернул точный Ереван (1 144 700
жителей) вместе с префиксными Еревани/Ереванлы/Ереванский Квартал. Даже с qualifier
«Армения» остались Ереван и Еревани. По документации Location Search используется
нормализованный prefix matching. Исправление — приоритет точного нормализованного
названия, затем ранжирование по population. Требование методички (строки 1073–1076)
об уточнении настоящих одноимённых мест сохранено; близость координат не используется
как основание склеивать разные населённые пункты.

Последующее явное пожелание пользователя 16.11.2026: сразу давать погоду для

Оно реализовано как удобный режим population; strict оставлен для нормативного
