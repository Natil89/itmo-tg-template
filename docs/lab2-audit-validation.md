# /why и аудит — проверка 17.11.2026

Реализованы персональный PostgreSQL-аудит решений и чтение последней записи командой
/why. Это отдельный этап лабораторной № 2; эксперимент на 12 запросах остаётся впереди.

## Границы и состояние

AuditTrace живёт в рамках одного сообщения/callback; состояние разных пользователей
не разделяется через поля агента. AuditStore владеет SQL и хранит только сокращённые
этапы. Handler берёт owner из Telegram, передаёт trace агенту и сохраняет результат.
Уникальный (user_id, request_key) защищает повтор; последний запрос определяется по
started_at, а не порядку завершения SQL. Изменение схемы добавляет новую таблицу и индекс.

Для чтений сохраняются проверка и выполнение каждого вызова. Для записей подготовка
помечается awaiting_confirmation, а callback создаёт отдельное событие результата.
Ошибка после успешного чтения дописывается отдельным этапом. Сбой аудита не повторяет
бизнес-действие и не превращает сохранённое напоминание в ложный отказ.

## Требования и доказательства

| Требование | Доказательство |
|---|---|
| A1: owner isolation и /why без побочных эффектов | test_why_handlers.py: owner из from_user, latest без save/LLM/MCP; PostgreSQL latest разных owners |
| A2: этапы/длительность/постоянное хранение | test_audit.py; PostgreSQL concurrent event-key, порядок started_at, повтор initialize и переподключение |
| A3: безопасные аргументы и отсутствие секретов | safe_arguments whitelist, lengths для текстов; тесты forged ids/unknown tool/secret redaction, render без request IDs |
| A4: ошибки и подтверждения | test_audit_agent.py: лимит2, два чтения, невалидный вызов/output, ошибка финального LLM; test_why_handlers.py: pending/confirm/cancel/foreign/error |
| A5: respond/clarify без regex routing | отдельный JSON-schema request + Pydantic, тест invalid/extra fields, timeout/error fallback undetermined |
| A6: сбой диагностики не повторяет действие | handler tests: audit-save failure, один вызов MCP/agent, сохранение бизнес-ответа; /why read error safe |

Причины — фиксированные публичные подписи приложения, без скрытых рассуждений.
JSON-классификатор получает только публичный ответ; у него нет tools, истории и
рабочего промпта. Классификация не участвует в разрешении действий. Для обычного
ответа она добавляет один запрос с ожиданием не более 10 секунд. Лимит двух MCP-вызовов
сохраняется. Если классификатор недоступен, исходный ответ выдаётся с честным
undetermined в диагностике. Для отказа/недоступности формулировка нейтральная:
«выбран ответ без вызова инструмента».

## Независимая проверка

Статическое ревью storage/agent/LLM/handlers/main не нашло блокирующих обходов или
утечек. По замечаниям добавлены redaction raw/decoded пароля прокси и нейтральная
причина ответа без инструмента. Этап ошибки после успешного чтения сохраняется отдельно.
