# Доставка напоминаний: приёмка этапа

Дата: 23.11.2026. Файлы: app/delivery.py, app/delivery_telegram.py;
подключение — app/__main__.py, конфигурация — app/config.py.

Более поздний этап города и сводки: lab3-briefing-validation.md. Упоминание их
как будущих возможностей ниже относится к состоянию проверки напоминаний.

DeliveryStore владеет постоянными событиями, попытками и арендами в PostgreSQL.
ReminderDeliveryService применяет правила времени и повторов. Sender — небольшой
контракт транспортного адаптера; в тестах он подменяется FakeTelegram. Middleware
берёт адрес только из private update. Модель не участвует ни в выборе адреса,
ни в запуске фоновой доставки.

Композиция отделяет Telegram от правил доставки. Альтернатива — держать SQL-lock
во время сетевого запроса — удерживает соединение и транзакцию на время сети;
выбрана постоянная аренда с отдельным подтверждением результата. Её цена —
восстановление просроченной аренды и остаточный риск повторной отправки.

## Требование → доказательство

| Требование spec.md | Проверка |
|---|---|
| D1: постоянный event_id, уникальная подготовка | Два последовательных prepare и два конкурентных prepare для свежего события; в БД одна строка |
| D2: доверенный адрес, отдельный actor | Middleware unit-тест; в БД actor=101 и destination=9001; подмена задания на destination=9999 не вызывает sender |
| D3: конкуренция и перезапуск | Два одновременных run_once дают одну отправку; незавершённый sending восстанавливается после закрытия и открытия пула, истечения lease |
| D4: опоздание/будущее | Ровно 15 минут: send с пометкой; 15 минут + 1 микросекунда: missed без попытки; будущее: pending без send |
| D5: ограниченные повторы | Fake временная ошибка: попытки в 0/30/150 секунд, затем failed, четвёртой нет; постоянная ошибка: одна попытка |
| D2/D3/D4: граница во время БД | Fake clock пересекает deadline или lease во время authorized; после свежей проверки sender не вызывается |
| D6: безопасный запуск | Конфигурация по умолчанию false, true/false проверяются, неизвестное значение отклоняется; .env пользователя не изменяется |

## Безопасная демонстрация и ограничения

Тесты не обращались к реальному Telegram/LLM и не использовали рабочую БД.
Время перемещалось fake clock, ожидания реальных минут нет. Рабочий бот не
перезапускался, реальная доставка не включалась, .env не изменялся.
Конкретная ручная демонстрация одного нового напоминания приведена в README.

Статусы: pending → sending → sent; при временной ошибке retry, при постоянной
или исчерпании попыток failed, при старом сроке missed. Lease 60 секунд, send timeout
10 секунд. Прерванный захват расходует одну из трёх попыток, даже если процесс
не успел вызвать Telegram. Повтор после незафиксированного успеха может дать дубль.

При выключенной функции не создаются новые адреса и не выполняется доставка.
Уже сохранённые данные не удаляются. При включении применяются обычные сроки;
старые напоминания не отправляются массово вне 15-минутного окна.
Сводка, /city, /notifications, /trace и полный эксперимент остаются следующими этапами.
