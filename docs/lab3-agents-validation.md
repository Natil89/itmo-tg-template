# Лабораторная 3: специалисты и подтверждение занятия

Дата проверки: 23.11.2026. Это приёмка текущего этапа, не всей ЛР3.

Более поздний этап доставки напоминаний: lab3-delivery-validation.md. Упоминания
отсутствующей доставки ниже относятся к состоянию проверки агентов, не к новому этапу.

## Что изменено

Основной путь приложения: Telegram → AssistantService → Router → Supervisor →
один специалист → ScopedMcp → MCP. В translate/quiz сохраняется текстовый режим
без инструментов; в study обычные объяснения также могут идти без MCP.
Значение dialogue в RouteDecision отличает этот путь от неоднозначной новой задачи.
operation уточняет read/prepare_reminder/prepare_lesson, но не даёт права исполнения.

Knowledge получает реальное содержимое каталога и найденные фрагменты, добавляет
источники. Lifestyle обосновывает совет погодой и сохраняет отметку population.
Schedule читает дату/текущую неделю и подготавливает напоминание. Отдельный
LessonCompatibility сохраняет возможность add_lesson, не расширяя права Schedule.
В основном запуске прежний универсальный ScheduleAgent больше не используется.

Кнопка и точный текст подтверждения занятия вызывают один confirm_lesson.
После отправки карточка привязывается к Telegram message_id и private chat_id.
Текст не подтверждает непоказанное, чужое, просроченное или неоднозначное действие.
В translate/quiz для согласия требуется reply на карточку. Поля БД добавляются
через ADD COLUMN IF NOT EXISTS без удаления данных. Старые карточки не получают
привязку задним числом; их действующие кнопки продолжают работать.

Все Python-команды выполнялись в WSL из корня проекта. Реальные LLM/Telegram
в автоматических тестах подменены. Рабочая PostgreSQL не использовалась.

- `.venv/bin/python -B -m pytest -q` — **606 passed, 7 skipped**, 151.33 секунды.
  Пропуски — отдельные Docker-интеграционные тесты, выключенные без RUN_INTEGRATION.
- Перед этим первый полный запуск дал 602 passed, 4 failed, 7 skipped: старые
  фиктивные MCP-клиенты в тестах аудита не предоставляли discovery. Добавлены реальные
  входные схемы в фикстуры; проверки порядка аудита и числа исполнений не ослаблены.
  Повтор `tests/test_why_handlers.py` — **33 passed**, затем общий прогон выше.

## Независимое ревью и ограничения

Read-only ревью выявило и помогло исправить: случайное согласие в другом режиме,
потерю контекста уточнений, отсутствие проверки discovery при подтверждении,
сравнение разных ISO-записей одного момента, подмену прошлой недели текущей и
возможность подготовки занятия фоновым intent. Проверки выполнял основной агент.

Реальный Telegram не вызывался для отправки, второй polling не запускался,
работающий бот не перезапускался. Для применения изменений пользователь
перезапускает свой единственный процесс обычной командой запуска.

Не завершены: трассы PostgreSQL и /trace, проактивные настройки, постоянная очередь
и доставка, ежедневная сводка, эксперимент 15 запросов на реальной модели,
полная таблица шести сценариев безопасности и итоговый отчёт. Текущие unit-тесты
безопасности не подменяют эту полную приёмку.
