# MCP: инструменты и ресурсы

Постоянный идентификатор: `mcp`.

MCP (Model Context Protocol) задаёт способ взаимодействия приложения с сервером,
который предоставляет инструменты и ресурсы. В этой лабораторной приложение
подключается к собственному MCP-серверу через stdio. Telegram-обработчик не должен
содержать SQL или копии схем MCP.

Клиент обнаруживает инструменты через `tools/list`. Инструмент вызывается через
`tools/call`: клиент передаёт имя и аргументы, а сервер проверяет их и возвращает
данные или ошибку. Например, `get_schedule` читает занятия на указанную дату.
Само обнаружение инструмента не даёт агенту право его вызвать: приложение
пересекает возможности сервера с программной политикой конкретного компонента.

Ресурс предоставляет данные для чтения по URI. Клиент получает список через
`resources/list` и содержимое через `resources/read`. В нашем проекте
`materials://catalog` перечисляет документы, а `schedule://current-week` содержит
недельное расписание. URI в списке ещё не означает, что модель получила содержимое:
приложение должно прочитать ресурс и передать разрешённые данные в контекст.

MCP связывает приложение с инструментами и данными. Внутренний вызов специалиста
через Python-контракт не является реализацией сетевого протокола A2A.

Источник: методичка `docs/labs-guide.md`, лабораторные 2–3, разделы
«Инструмент и ресурс», «Доступ компонентов к MCP-инструментам», «Граница реализации A2A».
