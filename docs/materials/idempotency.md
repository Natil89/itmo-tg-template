# Идемпотентность и доставка уведомлений

Постоянный идентификатор: `idempotency`.

Идемпотентность означает, что повтор операции не создаёт нового эффекта сверх
первого успешного выполнения. Для подготовки уведомления это означает одно
постоянное задание на одно событие, даже при повторном или конкурентном запуске.
Приложение назначает постоянный ключ события и сохраняет задание в PostgreSQL
до отправки. Уникальное ограничение в БД защищает от конкурентного создания дублей.

Подтверждение и доставка — разные этапы. Модель предлагает напоминание, пользователь
подтверждает показанные параметры, приложение сохраняет запись. Когда время
наступает, фоновый исполнитель доставляет её без нового решения языковой модели.
Адрес доставки берётся из доверенного update личного чата, не из текста модели.

В этой лабораторной напоминания с опозданием до 15 минут включительно доставляются
с пометкой о задержке. Более старые получают статус `missed` и не отправляются.
Ежедневная сводка назначается на 08:00 местного времени; допустимое опоздание —
60 минут включительно. Для пользователя и локальной даты создаётся одна сводка.

При временной ошибке допускается не более трёх попыток всего. При постоянной
обработка прекращается. Состояния и попытки хранятся постоянно, чтобы продолжить
незавершённую обработку после перезапуска с учётом допустимого опоздания.

Telegram `sendMessage` не предоставляет универсальный ключ идемпотентности.
Если сообщение уже отправлено, а фиксация успеха в БД не произошла, повтор может
доставить дубль. Уникальность задания не доказывает exactly-once доставку.
