## Метод

Использован исходный `docs/evaluation/lab2-routing.json`, все 12 запросов без изменения
ожидаемых результатов. В JSON сохранён SHA-256 набора. Время эксперимента по набору —
**2026-10-12 09:00:00, Europe/Moscow**; фактический запуск — **2026-11-17**.
Фиксированное время используется только внутри эксперимента.

Настроенная модель: **deepseek/deepseek-v4.1-flash**, temperature **0.3**, max_tokens **1000**,
reasoning отключён, режим study, пустая история для каждого запроса. Все 21 HTTP-ответ
API сообщили один идентификатор модели. OpenRouter автоматически выбирал провайдеров;
их имена сохранены по каждому ответу, один конкретный провайдер не фиксировался.

Используется настоящий LlmClient и ScheduleAgent, схемы извлечены из обработчика
MCP `list_tools` текущего сервера. Среди доступных инструментов все четыре:
get_schedule, get_weather, add_lesson и add_reminder. Ожидаемые ответы не передаются
модели. Хеши исходников и схем сохранены до запуска.

Данные чтения воспроизводимы: пустое расписание и фиктивная погода с 10 °C, ветром
2 м/с и облачностью. Это **тестовые данные**, а не реальные погодные наблюдения.
FixtureMcp подменяет транспорт/источники после того, как модель выбрала действие.
Напоминания нормализуются доменной функцией приложения и подготавливаются в памяти.
Рабочая БД, отправка Telegram и выполнение записывающих MCP-инструментов не используются.
Транспорт MCP и PostgreSQL отдельно проверялись интеграционными тестами предыдущих этапов.

Оценка относится к **первому** native-решению. Несколько предложенных инструментов
считаются несовпадением с единственным ожидаемым действием. Все девять запросов,
требующих инструмента, входят в знаменатель аргументов, включая ошибочный/пропущенный
вызов. Для города значима запятая перед страной; для даты требуется точное значение;
для напоминания проверяются ISO-формат, момент и UTC-смещение. В тексте напоминания
не влияют регистр, ё/е и завершающая пунктуация. Другие переформулировки не засчитываются
автоматически.

**Ошибочных случаев не обнаружено**, поэтому изменение промпта/описания инструмента
и повтор отдельных случаев не требовались. Выполнен один полный базовый прогон;

## Воспроизведение

Из корня проекта с настроенным `.env`:

```bash
.venv/bin/python -B -m scripts.evaluate_lab2 \
  --output docs/evaluation/results/lab2-new-run.json
```

Каждый запуск требует нового имени выходного файла. Отчёт сохраняется после каждого
случая; завершённый прогон получает status=complete и Markdown-таблицу.
Модель берётся из LLM_MODEL; для сравнения с этим прогоном используйте тот же идентификатор.
Результаты стохастической модели при повторе могут отличаться.

В случае будущих ошибок доступен повтор только неудачных ID:

```bash
.venv/bin/python -B -m scripts.evaluate_lab2 \
  --retry-from docs/evaluation/results/lab2-new-run.json \
  --change-note "Описание единственного изменения" \
  --output docs/evaluation/results/lab2-retry.json
```

Частичный повтор имеет собственные знаменатели и не выдаётся за новый полный прогон.
